## 🎯 How to Use These Materials

### Before the Module Starts:
1. Read through **MEMORY_GAME_LECTURE_PLAN.md** completely
2. Review the actual project brief from HackYourFuture
3. Set up your demo Memory Game
4. Prepare card images and resources
5. Assign pairs (coordinate with staff)
6. Set up Trello template board
7. Review code examples and test them

### During Each Session:
1. Keep **MEMORY_GAME_QUICK_REFERENCE.md** open for quick lookups
2. Follow the time breakdowns (but adjust as needed)
3. Use live coding examples from the main guide
4. Share relevant student templates at appropriate times
5. Check in with pairs regularly

### Between Sessions:
1. Review student PRs and provide feedback
2. Check Trello boards for progress
3. Prepare for next session's topics
4. Test any new code examples
5. Reach out to struggling pairs

## 🎮 Project Overview

**What Students Build:** A classic Memory/Concentration card game where players flip cards to find matching pairs.

**Technical Requirements:**
- **Frontend:** HTML, CSS, JavaScript (card flip animations, grid layout, game logic)
- **Backend:** Node.js, Express (RESTful API to serve card data)
- **Database:** PostgreSQL (store card information, optionally scores)
- **Deployment:** Netlify/Vercel (frontend) + Heroku/Railway (backend)
- **Project Management:** Trello with MoSCoW prioritization

**Learning Goals:**
- Pair programming collaboration
- Full-stack development
- Project management
- Self-guided learning
- Deployment and presentation skills

## 💡 Teaching Philosophy

These materials are built on key principles:

1. **Hands-On Learning:** Maximize coding time, minimize lectures
2. **Real Collaboration:** True pair programming, not one person watching
3. **Problem-Solving:** Guide students to find answers, don't just give them
4. **Celebration:** Acknowledge progress and effort consistently
5. **Support:** Create safe space for questions and struggles
6. **Real-World Skills:** Project management, Git, deployment matter as much as code

## 📊 Assessment Overview

**Grading Breakdown (100 points):**
- Functionality (30): All milestone features working
- Code Quality (15): Clean, organized, readable
- Frontend (15): Good UI/UX, responsive, animated
- Backend (15): Working API and proper database

## 🆘 Common Challenges & Solutions

### Student Challenges:
1. **Git collaboration issues** → Teach branch strategy, help with conflicts
2. **Async JavaScript confusion** → Use async/await, show step-by-step
3. **Backend overwhelm** → Start simple, test with Postman first
4. **Time pressure** → Help prioritize, emphasize MVP
5. **Pair dynamics** → Check in privately, facilitate communication

### Instructor Tips:
- Have backup examples ready
- Test all code before class
- Adjust pace based on class progress
- Encourage peer helping
- Make it fun!

## 🎤 Presentation Day

**Format:** 7-10 minutes per team

**Structure:**
1. **Trello Board** (2 min) - Show workflow and organization
2. **Live Demo** (3-4 min) - Play the game, demonstrate features
3. **Contributions** (2-3 min) - Each person explains their work
4. **Q&A** (1-2 min) - Answer questions

**Setup:**
- Share QR codes to live projects
- Supportive, encouraging atmosphere
- Test games on devices during presentations
- Applaud every team
