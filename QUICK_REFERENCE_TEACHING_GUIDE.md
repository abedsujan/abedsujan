## 🎯 Core Teaching Strategies

### The "3 Ps" Framework
1. **Preparation:** Well-structured lessons, tested demos
2. **Presence:** Energy, enthusiasm, attentiveness
3. **Patience:** Allow time for understanding, repeat concepts

### Engagement Techniques (Use Every Session)
- ✨ Start with a hook or interesting fact
- ✨ Ask questions every 10-15 minutes
- ✨ Live coding with student input
- ✨ Pair/group activities
- ✨ Real-world examples
- ✨ Breaks every 45-50 minutes
- ✨ End with clear summary and next steps

### The "I Do, We Do, You Do" Model
1. **I Do:** Demonstrate the concept
2. **We Do:** Practice together with guidance
3. **You Do:** Independent practice

## ⚡ Quick Tips for Each Topic

### HTML
- Always start with semantic elements
- Show bad examples (div soup) vs. good
- Use DevTools to inspect real websites
- Emphasize accessibility = better for everyone

### CSS
- Mobile-first approach
- Teach debugging with DevTools first
- Provide visual diagrams for layouts
- Live code common patterns (nav, cards, grid)

### JavaScript
- console.log() is your friend
- Break down into small functions
- Use debugger statement
- Encourage reading error messages

### Git/GitHub
- Practice basic workflow repeatedly
- Provide a cheat sheet
- Show how to undo mistakes
- Make it less scary through practice

## 🆘 Common Issues & Quick Fixes

| Issue | Quick Solution |
|-------|----------------|
| Students lost/overwhelmed | Break task into smaller steps, check in 1-on-1 |
| Boring lecture | Switch to hands-on activity, ask questions |
| Technical difficulties | Have backup plan, use student's screen |
| Wide skill range | Provide extension activities + extra support |
| Low engagement | Change activity, take break, use energizer |
| Can't debug issue | Rubber duck method, pair programming |

## 🎤 Presentation Day Tips

**Before Presentations:**
- Create supportive atmosphere
- Remind audience to be encouraging
- Set time limits clearly
- Have backup plan for technical issues

**During Presentations:**
- Keep time
- Take notes for feedback
- Ask 1-2 questions per presentation
- Highlight specific strengths

**After Presentations:**
- Celebrate everyone's work
- Provide written feedback within 24 hours
- Share photos/recordings (with permission)
- Discuss next steps/career opportunities

## 💬 Great Questions to Ask During Class

**To Check Understanding:**
- "Can someone explain this in their own words?"
- "What do you think will happen if we run this code?"
- "Why did we use X instead of Y here?"

**To Encourage Thinking:**
- "How would you approach this problem?"
- "What other ways could we solve this?"
- "What might go wrong here?"

**To Build Connection:**
- "Has anyone encountered this in real life?"
- "Where might you use this in your project?"
- "What questions do you have?"

2. Preview homework
3. Take questions
4. End on positive note
5. Stay available after for questions
